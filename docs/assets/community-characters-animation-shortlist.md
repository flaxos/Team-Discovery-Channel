No third-party model/animation files were downloaded. Geometry counts below are source metadata; downloaded formats, bone lists, skinning quality, material maps and playable clips remain unverified unless stated otherwise.

## Evidence and access boundaries

Sketchfab model pages returned HTTP 403 to the research browser. Their anonymous, official public metadata API was accessible; its `license.url`, creator, `isDownloadable`, `faceCount` and `animationCount` fields were read directly. Each Sketchfab row links that primary evidence. A downloadable flag means the publisher currently offers downloads, not that the archive was obtained or inspected. Sketchfab's [download API documentation](https://sketchfab.com/developers/download-api/downloading-models) requires a signed-in account and an authenticated request; do not scrape viewer mesh buffers as a substitute. Available source/download formats must be checked through that authorized workflow. No login, purchase, acceptance of terms or creator contact was performed.

An uploader's display name and a CC license record identify the offered grant; they do not by themselves prove chain of authorship or clear a depicted franchise/likeness. Record creator statements and bundled license evidence when obtaining the archive. The owner's permission for community-created Stargate fan art in the [pipeline](../plans/asset-import-pipeline.md#provenance-and-redistribution) does not turn an NC license into a commercial grant or establish underlying franchise rights.

## License findings that affect the insertion plan

The three tactical Sketchfab candidates and the AJS helmet explicitly expose [CC-BY-4.0](https://creativecommons.org/licenses/by/4.0/) in live metadata. Preserve title, creator, canonical URL, license text/link and modification notes with each obtained asset. No model in this register has passed the repository's complete provenance/import gate yet.

Quaternius distributes packs under either CC0 or QAL and directs users to each pack’s bundled licence. The acquired Universal Animation Library Standard tier identifies CC0 in both `License.txt` and `README.txt`. Other libraries and tiers need their own archive checks. [Creator FAQ](https://quaternius.com/faq.html) · [Standard intake record](intake/sprint19-airman/ual1-standard.json).

The Mixamo help FAQ establishes free/royalty-free project use, while the Adobe-hosted distribution FAQ describes the raw-file restriction. That community FAQ is supporting guidance rather than a replacement for the accepted terms. Adobe's [Fuse-specific terms, 18 June 2024](https://wwwimages2.adobe.com/content/dam/cc/en/legal/servicetou/Fuse-Product-Specific-Terms-en_US-20240618.pdf), separately allow Animation Data distribution only with an embedded End Use and prohibit separate distribution; they identify themselves as **Fuse terms**, so their applicability to a particular Mixamo acquisition must not be assumed. The safe repository plan is to keep raw Adobe content out until the actual grant and distribution workflow are established. Converting FBX to GLB does not by itself change the content license.

One attractive-looking Jaffa lead was excluded: **[Stargate Jaffa Helmet by lexruel](https://sketchfab.com/3d-models/stargate-jaffa-helmet-45e9dcaa597c4c23bcb0e829123df0ef)** is explicitly **CC-BY-NC-4.0** in [its primary metadata](https://api.sketchfab.com/v3/models/45e9dcaa597c4c23bcb0e829123df0ef). It is an eagle-style static helmet (24,130 triangles; no animation), not a cleared CC-BY asset or retractable serpent rig. Owner permission for CC-BY fan assets does not include that NC grant.

These are source-code observations, not promised asset features:

| Existing scene/controller | Current contract that an imported rig must respect |
|---|---|
| [`Player.tscn`](../../client/scenes/entities/Player.tscn) / [`PlayerController3D.gd`](../../client/scripts/entities/PlayerController3D.gd) | Root `CharacterBody3D` owns movement/collision; the capsule is centered at Y=0.9. `Visuals/BodyMesh`, `Visuals/VisorMesh` and `Visuals/ClassGear` are referenced by code. `WeaponHolder` is a root sibling, initially `(0.3, 0.9, -0.4)`; aiming rotates the holder. It is not a hand-bone attachment. Current crouch/downed/dragging presentation is procedural, not an `AnimationTree`. |
| [`SGCAirman.tscn`](../../client/scenes/entities/SGCAirman.tscn) / [`SGCAirmanAI.gd`](../../client/scripts/entities/SGCAirmanAI.gd) | `Visuals/BodyMesh` transform is in replication config; the controller changes its Y scale/position for crouch/downing. | [`JaffaGuard.tscn`](../../client/scenes/entities/JaffaGuard.tscn) / [`JaffaAI.gd`](../../client/scripts/entities/JaffaAI.gd) | Code expects `Visuals/ArmorMesh` as `MeshInstance3D`, `Visuals/StunFX`, root `StaffMount` and `StaffMount/MuzzlePoint`. For later character fits, preserve root hit capsules, damage, perception eye-height rules, navigation, class/inventory state and server ownership. Use each held weapon model's cosmetic transform for grip changes and keep the firing origin at the gameplay marker.

## Animation coverage to verify before selecting a library

| Required gameplay motion | Evidence currently available | Remaining acceptance |
|---|---|---|
| Idle, walk/strafe/backward, run/sprint | UAL 1 advertises directional locomotion; full archive/tier clip membership unknown. Soldier metadata exposes at most one animation each. | Same clip timing and foot phase across blends; match controller speed without moving the gameplay root. |
| ADS and aim pitch | No candidate archive's aim offsets/upper-body masks verified. | Weapon muzzle follows the intended aim; lower-body locomotion remains stable; both hands fit P90, MP5, M249 and staff grips. |
| Crouch, low cover and peek | Current game already uses crouch/peek states; no complete imported set verified. | Eye/cover readability and collision stay consistent; transitions do not retain procedural squash. |
| Reload | No P90/MP5/M249/M9-specific reload set verified. | Reload duration/event timing follows existing weapon mechanics; detachable magazine sockets are optional visual work, not new ammo authority. |
| Stun, downing and death | UAL 1 advertises death; exact stun/downed/crawl clips unknown. | Correct final pose, awareness marker/stun FX and vaporization on every peer. |
| Revive and body dragging | No verified paired/revive/drag set in any observed free tier. | Requires matched actor/victim offsets and transitions; existing server health/drag mechanics remain authoritative. Budget bespoke clips if no cleared set exists. |

Godot 4.4's [retargeting documentation](https://docs.godotengine.org/en/4.4/tutorials/assets_pipeline/retargeting_3d_skeletons.html) explicitly says matching names alone is insufficient: rest transforms and hierarchy also matter, and automatic mappings can require correction. A `SkeletonProfileHumanoid` helps map rigs; it does not guarantee that one library animates every character, hand socket or bulky helmet correctly. [AnimationTree](https://docs.godotengine.org/en/4.4/tutorials/animation/animation_tree.html) is the eventual blend/state layer; it is not already integrated in these controllers.

## First insertion experiment and measurable acceptance

1. **Obtain one candidate, not a whole catalog.** Use candidate 1 through authorized Sketchfab download. Preserve the original archive outside `client/`, its license text, canonical/metadata URLs, date, creator, archive checksum and modification log. Verify authorship evidence and exact source format. Separately resolve UAL 1's archive license before using its clips. Keep the existing capsule visuals as a fallback.
2. **Inventory offline in Blender/Godot.** Record metric bounds, forward axis, root transform, mesh/material counts, vertex influences, skeleton bone names/parents/rest pose, animations with durations/loop/root-motion flags, texture resolutions and actual map channels. Record unknowns as failures to inspect, not values inferred from a product title. Convert a working copy to a self-contained GLB; retain source provenance.
3. **Prove one Airman visually first.** Add a rigged child through an adapter rather than renaming the authority root or deleting referenced nodes. Start with idle and one in-place walk cycle, then crouch and a single supported death/downed transition. Use a reviewed `BoneMap`; add hand/head sockets only after mapping real bone names. Disable conflicting procedural visual transforms for the imported presentation, with fallback behavior retained.
4. **Keep motion and firing owned by the existing game.** Drive the visual blend from velocity, crouch/aim and health/combat state. Start with in-place clips: current authoritative `CharacterBody3D` movement and TA-3 navigation must remain the physical source of motion. If root motion is ever chosen later, it needs an explicit authority/replication design. Align the held mesh with the existing muzzle before changing firing paths.
5. **Inspect in SGC and the offworld compound.** Capture Forward+ close and normal gameplay views, matte/material treatment under current D-015 lighting, weapon/hand contact, silhouette with the awareness tell, crouched cover and head clearance through doors. Verify normal-map orientation from the actual maps. High-poly or 8K source detail is not a substitute for a measured frame/memory/LOD budget with the actual NPC population.
6. **Verify gameplay and networking.** A late join sees the current stance/held weapon/downed state; travel and retry preserve the gameplay state; local visual animation never authorizes damage, teleporting, reload completion or revive. Run relevant AI, combat, cover, revive, travel, late-join and new adapter tests plus the full regression. Compare collision and firing/perception behavior before/after, then obtain the human visual review. Only the accepted files and attribution/license evidence enter the repository.

The first reviewable outcome is one Airman in idle/walk/crouch with a legal, measured rig and unchanged gameplay behavior. A complete SG-1/Jaffa animation overhaul, paired interactions and uniform/faction artwork are later pieces with their own acceptance evidence.
